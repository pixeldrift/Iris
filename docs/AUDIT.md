# Code audit

What was checked, what was fixed in this pass, and what is left (with a recommendation for each). Everything below was measured on
the code as it stands, in headless Chromium and unit tests; nothing here was tried on a real phone or with a screen reader.

## Done in this pass

| Area | Change |
| --- | --- |
| Colour tokens | The warning family was hand-typed four ways in 16 files (`#c4577e`, `#c95b88`, `#b04a6e`, `#9a4566`). It is now `--color-danger`, `--color-danger-ink` and `--color-danger-deep` in `src/index.css`, used as `bg-danger`, `text-danger-ink`, `hover:text-danger-deep`. The error dot (`#c95b88`) became plain `danger`. |
| Palette drift | The palette lived twice: `src/index.css` and the colour slider's table. The table moved to `src/ui/palette.ts` and `src/ui/palette.test.ts` fails if the two disagree. |
| Slider default dot | `DefaultDot` takes `var(--color-ink-faint)` by default (three components typed a near-miss hex `#a39cb0`). |
| "Is it done?" | Six views answered differently (status only, or status plus the repeat log). A repeating task ticked today showed a filled check but an un-struck title in the list, board, bubble and Space. One function, `isDoneNow` (`src/core/recurrence.ts`), now answers for DoneButton, bubbles, list, board, priority and Space, with tests. |
| Dialogs | `Modal` had no keyboard focus handling. It now moves focus into the dialog, keeps Tab and Shift+Tab inside, and returns focus to where it was on close (`e2e/dialogfocus.spec.ts`). Closing handlers no longer restart the effect on every render. |
| Touch targets | Check circles (16 to 22 px) keep their look but get an 8 px larger tappable area on coarse pointers. |
| Filtering cost | `matchesScope` rebuilt a group's descendant set for every task (tasks x groups x depth). `scopeMatcher` does it once per scope; `useVisibleTasks` and `filterTasks` use it. The address book counted open tasks per person with a filter inside each row; it is now one pass. |
| Rendering | The Space view subscribed to its whole store, so every drag frame (which writes the layout) re-rendered it. It now selects only the preferences it shows. The 3D scene looked groups up with `find` for every task on every frame; it keeps a map. |
| Dead code | Removed `getLocalePrefs`, `stageAfterTicks`, `toLocalInput`, `fromLocalInput`, `readVCard` and seven icons that nothing references. |

## Findings not yet fixed

### Phase 1: consistency

1. **Native tooltips versus the app's own.** *Addressed (third pass):* the count was misleading (most `title` attributes are extra detail on text, e.g. a truncated task name). The real duplication was icon buttons carrying both an aria-label and an identical `title`: those now use `<Tip>`, and `src/ui/conventions.test.ts` fails if one comes back. Original note: 102 `title=` attributes against 17 `<Tip>` wrappers. `title` gives a delayed, unstyled bubble on desktop and nothing on touch. Recommend: icon-only buttons use `<Tip>` (it also supplies the accessible name); keep `title` only where the text is long help.
2. **Stacking order was ad hoc.** *Fixed (second pass):* the layers above 40 are now named variables in `index.css` (`--z-drawer`, `--z-panel`, `--z-modal`, `--z-toast`, `--z-popover`, `--z-tip`, and so on) and every component uses them. The values did not change, so nothing moved. The small local `z-10`/`z-20` inside a component are left as they are.
3. **Two modal implementations.** *Addressed (third pass), differently from the recommendation:* both keep their own look and motion (the day panel grows out of the tapped box, which `Modal` cannot do), but now share `useDialogKeys` with `Modal`: they are dialogs for screen readers, hold Tab inside, and give focus back. Original note: Calendar's event editor (`views/Calendar.tsx`) and the New Task sheet (`NewTask.tsx`) each build their own overlay. They do not share `Modal`'s Escape, focus and backdrop behaviour. Recommend moving both onto `Modal` (with a `placement` option for the top-anchored New Task).
4. **Space cards and flat rows repeat task presentation.** *Fixed (fourth pass):* one look and one set of rules. The look is the pond bubble's: `.pad` and `.tint` in `index.css` are now one rule (shine, glow, outline, shadow, deeper when urgent; ellipse gradients so a wide row is the same bubble stretched), and `src/core/look.ts` states the same numbers for the 3D cards, with a test that the stylesheet still contains them. The words and tone of the date chip come from `dueInfo` (`src/core/rowModel.ts`) for every renderer: `DueChip`, the flat row and the 3D card. The flat row is built from the real `DoneButton` and `DueChip`. The 3D card still has to be drawn on a canvas, but it only paints what the shared look and rules say. Only the list/board rows' `backdrop-filter` blur stays bubble-only (a long list of blurred rows is slow).
5. **Icon-only controls named only by `title`.** None found without a name in the desktop sweep; the landscape quick-add input and textarea are unnamed while closed (they are labelled when shown).
6. **Confirmation behaviour.** All confirmations go through `askConfirm`/`askChoices` (no native `confirm`), which is good. Destructive actions elsewhere (delete a task, delete a group) rely on Undo rather than asking; that is a deliberate pattern, but it is not written down. Recommend one sentence in `ARCHITECTURE.md`.

### Phase 2: UX

7. **Small targets** (*partly addressed:* check circles now have a larger tap area on touch screens, so Priority's smallest bubbles reach about 30 px; chips and mode buttons are unchanged) (measured on 390x844 and 844x390): Priority view check circles 13 to 19 px (they scale with importance, so the smallest bubbles are hardest to tick); Pond filter chips and Calendar mode buttons 22 to 24 px high; sidebar disclosure arrows 20 to 24 px. WCAG 2.2 AA asks for 24 px; platform guidance is 44 px. Recommend a minimum bubble size for the check in Priority, and `min-h-9` on chips under `(pointer: coarse)`.
8. **The edge-swipe handle is 19 px wide and the full height.** It is intentional (swipe from the edge to open the menu) but it is also reported as a button named "Open menu"; a visible Menu button exists, so this is fine. Worth testing against the iOS back-swipe gesture on a real phone.
9. **Timeline offscreen content.** 150 to 220 elements extend past the viewport edge. That is the scrolling timeline, not a layout bug, but it has no keyboard scroll affordance or "jump to today" at phone size.
10. **Empty and error states** are written per view. *Addressed for lists (third pass):* `EmptyState` is used by List and Timeline; when a filter or search is what is hiding things it says so and offers "Show everything". Board columns, Calendar days, Overview and the address book keep their own sentences, on purpose (they are not "nothing matches" cases). Original note: Recommend one `EmptyState` component (icon, one sentence, one action) so every view says the same kind of thing the same way; errors already go through `showToast`.
11. **Keyboard.** *Addressed for list and board (third pass):* rows are reachable by Tab, Up/Down/Home/End move between them, Enter or Space opens one (`e2e/rowkeys.spec.ts`). Pond bubbles and the Space canvas are still pointer-first. Original note: `Modal` is now correct. Popover menus handle Escape; the sidebar tree, Pond bubbles and the Space canvas are pointer-first. Space has a screen-reader list of tasks, but arrow-key navigation between bubbles and groups does not exist. Recommend roving focus for list and board rows first (they are real lists).
12. **Discoverability.** *Addressed (third pass):* Settings has a folded "Tips and gestures" list under Help. Original note: Drag to retag in Space, spring-loaded folders, drop onto the sidebar, and the colour slider's reset dot are all unlabelled until tried. Space has a one-time tip; the others have none. Recommend a short "Tips" row in Settings that lists the gestures.

### Phase 3: architecture and performance

13. **Large files.** *Partly done (third pass):* `Pond.tsx` lost its group-name block to `pond/GroupLabel.tsx` (1071 to 995 lines) and the 3D scene's connector geometry moved to `spatial/links.ts` (pure and tested). The pond's physics loop and the scene's carry/pick code are one tightly shared closure of mutable refs; splitting them is a rewrite with real risk to feel, so it was left alone deliberately. Original note: `Pond.tsx` (1071 lines), `SpatialScene.ts` (1019), `Calendar.tsx` (786), `TaskDetail.tsx` (553), `PeopleDialogs.tsx` (550). `Pond.tsx` mixes physics, gestures, labels and the pop game; `SpatialScene.ts` mixes rendering, picking, carrying and links. Recommend splitting along those seams (`pond/useLabels`, `spatial/carry.ts`, `spatial/links.ts`) with behaviour unchanged.
14. **Undo bookkeeping runs on every data change.** *Re-checked, corrected:* `state/history.ts` takes reference snapshots (one filter for drafts, then a reference comparison of each list). That is linear and cheap; the earlier note that it deep-compares was wrong. Nothing to do unless profiling says otherwise.
15. **Duplicated "walk the group tree".** *Fixed (second pass):* the Space scene and flat canvas both use `descendantsOf` from `src/core/tree.ts` (tested). `core/folders.ts` keeps its own `descendantIds` for real folders, which includes the start id and is used widely; `SpatialView`'s ancestor walk is a different question (is anything above me folded?) and stays.
16. **Persistence boundaries.** The app store (`lilac-v1`, versioned, migrated) is what syncs. The Space store (`lilac-spatial-v5`) is local by design: layout, folded groups, radius. Four small device keys (`lilac-dayplan`, `lilac-device`, `lilac-sidebar-w`, `lilac-weekends`) are read and written directly. Space layout does not follow a person to another device, and nothing says so. Recommend deciding whether folded groups and placements should sync (they are per-person view state, so probably per device, but then say it in the settings text).
17. **Timers.** *Re-checked, corrected:* the network polls (share, connect, update check) already skip their work while the page is hidden and run once when it comes back. The timers that do keep running (day schedule 30 s, "minute" tick for finished events, the example hints, the pop-game bank) only change local state. Reminders must keep running while hidden. No shared ticker needed.
18. **Unneeded exports.** About 60 exports are used only inside their own file (types, constants, helpers). Harmless, but they widen the public surface. Recommend `noUnusedLocals`-style linting with an export check in CI.

## How to re-run the checks

- Types and unit tests: `npx tsc --noEmit && npx vitest run`
- Palette sync: `src/ui/palette.test.ts`
- Dialog focus: `npx playwright test --project=app e2e/dialogfocus.spec.ts`
- Unused exports: the one-off script in this pass walked every `export` and looked for other files that mention the name; it is easy to turn into a CI step.
